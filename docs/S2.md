## Reproduce from the manifest

```sh
pip install -r requirements-ci.lock
python -m app.edgar_corpus reproduce --directory artifacts/edgar-html --user-agent "Your Organisation research contact@example.com"
python -m app.edgar_corpus verify --directory artifacts/edgar-html
python -m app.edgar_corpus reproduce --directory artifacts/edgar-fresh --user-agent "Your Organisation research contact@example.com"
```

Run from the repository root. Replace the example contact with your real research
contact. Filings must resolve under this repo's ignored artifacts/ directory;
symlink escapes and unsafe names/URLs are rejected. Requests are serial, at least
one second apart, at most eight per invocation, with a 30-second inactivity timeout
and a 12 MB decoded response cap. HTTP redirects, 403 and 429 stop without retry
or an alternate host. Hash mismatches never replace a previously accepted file.
Each file is atomically replaced only after validation; no manifest is published
until the create run finishes. A failed multi-file reproduction can leave earlier
verified files, and returns failure rather than claiming complete success.

These limits are below SEC's published 10 requests/second ceiling; a descriptive
User-Agent identifies project/contact. See [SEC access policy](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)
and [submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces).
An upstream change, denial or rate limit may prevent future reproduction; the
program fails rather than laundering a changed response into the frozen manifest.

Two initial urllib attempts rejected incomplete HTTP chunk transfers without
saving partial content or hashes. The implementation now uses the already-declared
httpx dependency and bounded decoded streaming. Complete HTML plus independent
matching downloads passed. This does not bypass a denial or accept partial bytes.
