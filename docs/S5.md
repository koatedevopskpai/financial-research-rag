## Exact scope

app/evaluation.py implements retrieval scoring separately from answer checks. The
demonstration adapter runs a real local BM25 calculation over eight self-authored
passages and an extractive quotation/abstention function. It is explicitly NOT the
Azure Search QueryPipeline, live LLM generation or an evaluation of the downloaded
EDGAR filings. The fixture has ten questions: eight answerable and two unsupported.
Its company names/figures are invented; it is not a benchmark or financial data.

The reusable retrieval scorer accepts observed ranked IDs and graded qrels.
Recall@5 uses all positive qrels as the denominator; MRR@5 is reciprocal rank of
the first relevant result in the top five; nDCG@5 uses exponential graded gains
(2^grade - 1) and log2 discount against ideal top-five order. Duplicate IDs and
invalid grades are rejected. Unsupported cases have null retrieval metrics, not
perfect scores, and are excluded from the eight-case retrieval mean. This is
truncated MRR@5, not an unbounded-rank corpus-wide MRR claim.

Answer evaluation checks exact quoted text against its cited retrieved document.
Free prose, unknown IDs, unsupported quotes and omitted quote citations fail the
answer contract. It checks matching evidence, not semantic entailment, completeness
or whether a supported quote actually answers the question. Abstention uses one
exact reference string. Decision accuracy covers all ten cases, so false abstention
on an answerable question is penalised as well as failure to abstain on unknowns.
Citation support is null when there are no quoted claims; an abstention is not
counted as a perfectly supported citation. Source matching is not financial truth.

## Dated observed results

| Run | Recall@5 | MRR@5 | nDCG@5 | Supported quotes / all quotes | Answer contract | Abstention decision accuracy | Gate |
|---|---:|---:|---:|---|---:|---:|---|
| none | 1.000 | 1.000 | 1.000 | 8/8 | 1.000 | 1.000 | True |
| retrieval | 0.000 | 0.000 | 0.000 | 0/0 | 0.200 | 0.200 | False |
| citation | 1.000 | 1.000 | 1.000 | 0/8 | 0.200 | 1.000 | False |
| abstention | 1.000 | 1.000 | 1.000 | 8/10 | 0.800 | 0.800 | False |

All rows use the same ten questions. Retrieval means have n=8; answer-contract and
abstention-decision rates have n=10. The citation column is weighted by actual
quoted claims, not by questions. The retrieval fault removes known relevant IDs
from the observed list; the other faults alter actual generated output. Each is
deliberate test injection, not a naturally occurring Azure/model failure.

The citation and abstention faults leave retrieval unchanged yet block acceptance.
This demonstrates that retrieval quality alone cannot make an unsupported answer
pass. The retrieval fault is also blocked independently; fluent output cannot
compensate for low retrieval scores. Every case/output is retained in the report.
Thresholds are versioned all-ones fixture contracts in eval/policy.json, chosen to
catch known regressions, not calibrated production targets. B01 remains deferred.

## Reproduce on Linux (Python 3.11, Git available)

```sh
pip install -r requirements-ci.lock
pip install --no-deps -e .
python -m app.tokenizer_assets --prepare
ruff check app/ tests/
mypy app/ tests/
python -m pytest tests/ -v --cov=app --cov-report=xml --cov-report=term-missing
python tests/evaluation_smoke.py artifacts/S5-ci
```

The smoke helper executes the actual CLI four times and verifies both exit status
and report contents. Baseline returns 0; each injected regression returns 1. The
helper succeeds only when those expected outcomes match. Reports record execution
mode, sample sizes, UTC time, tested Git revision, fixture/policy hashes, per-case
answers/rankings, separate metrics and failure reasons. CI runs the helper and
uploads ignored reports alongside coverage. A green workflow is not live quality.

Linux: ruff, strict mypy (35 files), 49 tests and all four CLI outcomes passed.
Coverage was 70% (1059 statements, 317 missed); gaps remain visible. No tests were
skipped or suppressed. No Azure/model calls, Docker application smoke, live corpus
answer run, remote Actions, push or merge is claimed by this task.

## Validation failures retained

Two earlier validation hosts passed lint/types but failed three report tests. The
first minimal Python container lacked Git; the second installed Git but its root
process could not trust the ec2-user-owned bind mount. The final runner installs
Git and assigns only the fresh task checkout to the container's root UID. It does
not disable Git's ownership check or change application/test assertions. All failed
attempt logs and cleanup receipts are retained. The passing run also performed
preliminary P01 offline checks at its recorded older source; P01's final corrected
source has its own later Linux validation and must not borrow that older pass.
